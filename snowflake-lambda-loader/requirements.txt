# Dependency set for the Snowflake Lambda loader handler.
#
# This is NOT `pip install cartography` — that pulls the full pyproject.toml
# dependency list (azure-mgmt-*, msgraph-sdk, oci, kubernetes, google-cloud-*,
# okta, every provider cartography supports), which is unnecessary bloat for
# a Lambda that only ever imports cartography.intel.snowflake. Same reasoning
# ../okta-lambda-loader/requirements.txt documents for Okta.
#
# Cartography's SOURCE (the `cartography/` package) is vendored separately
# at build time by the Makefile — see that file and README.md "Packaging
# strategy". Only the runtime dependencies actually reached by
# cartography.intel.snowflake's imports are listed here, discovered by
# reading cartography/intel/snowflake/util.py's own import block plus
# cartography/util.py, cartography/stats.py, and cartography/client/core/tx.py
# (every Snowflake sync transitively imports these three core modules).
#
# NOTE: cartography/util.py imports boto3/botocore even though this handler
# never calls any AWS API via the sync path itself — util.py's AWS-pagination/
# retry helpers are generic utilities cartography's core shares across all
# providers, not Snowflake-specific code. Same note
# ../okta-lambda-loader/requirements.txt makes for Okta. This handler's OWN
# code also uses boto3 directly, for ssm:GetParameter (see src/handler.py's
# _get_ssm_parameter).
